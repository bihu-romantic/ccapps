# 重调度接口协议

入口：`POST /{scenario}/api/reschedule/`
内容类型：`application/json`
鉴权：`Authorization: Bearer <API Key 或 webtoken>`。

---

## 1. 用途与分工

接口先写到对应的订单、物料或资源，再重调度。

受理后写入 `plan.skip_supply=1`。本次求解跳过 FAS/MRP 全量供应重建，在已有计划上按 hot/freeze 由 `solver` 修复（`cp` / `fas` / `mrp` / `ga`）。

- 订单：按每张单的 `action` 写数量、交期、物料。删单先从计划树记下腾出的资源，再删除该单的计划和需求
- 物料：写现有量，或写采购单的数量和到货
- 资源：把这段时间的产能写到该资源的产能日历

---

## 2. 请求

### 2.1 公共字段

| 字段               | 类型              | 必填   | 说明                                         |
| ------------------ | ----------------- | ------ | -------------------------------------------- |
| `category`       | string            | 是     | 触发类别，见下表                             |
| `level`          | string            | 否     | 范围级别，默认 `auto`                      |
| `solver`         | string            | 否     | `mrp`（默认）/ `cp` / `fas` / `ga`；共用 hot/freeze；均跳过全量供应重建 |
| `orders`         | object[]          | 视类别 | 每张单各自标动作，并带上新数量、交期。见 2.6 |
| `materials`      | object[]          | 视类别 | 现有量，或采购单数量和到货。见 2.7           |
| `resources`      | object[]          | 视类别 | 一段时间内的产能。见 2.8                     |
| `constraint`     | string            | 否     | 默认 `capa,mfg_lt,po_lt` |

### 2.3 category

| 值           | 中文别名         | 含义                                 |
| ------------ | ---------------- | ------------------------------------ |
| `order`    | 订单、订单变化   | 仅订单触发                           |
| `material` | 物料、物料变化   | 仅物料触发                           |
| `resource` | 资源、资源变化   | 仅资源触发                           |
| `all`      | 全部、一起、混合 | 多类触发合并为一次求解               |

规则：

- `order` / `material` / `resource` 不得夹带其他类别触发字段
- 多类问题可使用 `all` / `combined` / `mixed` 合并提交

### 2.4 level（冻结范围）

| 值       | 说明                  |
| -------- | --------------------- |
| `auto` | 默认                  |
| `1`    | L1：较紧冻结          |
| `2`    | L2：含邻居扩展        |
| `3`    | L3：近全局可动（全量重调度；不重建供应） |

### 2.5 三类问题定义

| 问题类型 | 触发条件 | 必填触发字段 | 调度含义 |
| -------- | -------- | ------------ | -------- |
| 订单 | 插单、删单，或数量、交期变化 | `orders` | 接口写上新数量和交期，再以该单为重排种子 |
| 物料 | 现有量变化，或采购数量、到货变化 | `materials` | 接口写上新现有量或采购到货，再以用到该物料的计划为重排种子 |
| 资源 | 停机或产能变化 | `resources` | 接口把这段时间的产能写到该资源的产能日历，再以该资源上的计划为重排种子 |
| 混合 | 上述两类或三类同时变化 | 对应类型字段 | 各类种子取并集后一次求解 |

### 2.6 订单动作（category=order 或 all）

每张单自己标动作，一次请求可以同时插、删、改不同的单。

```json
"orders": [
  {"name": "SO-1001", "action": "insert", "item": "成品A", "quantity": 100, "due": "2026-11-20T08:00:00"},
  {"name": "SO-1002", "action": "delete"},
  {"name": "SO-1003", "action": "change", "quantity": 50, "due": "2026-11-22T08:00:00"}
]
```

| `action` | 请求里带 | 接口做什么 |
| -------- | -------- | ---------- |
| `insert` | 订单号、物料、数量、交期 | 写入需求的物料、数量、交期，再为这张单生成计划。需求行须已存在，且还没有计划 |
| `delete` | 订单号 | 从计划树记下腾出的资源，再删除需求和计划 |
| `change` | 订单号、新数量、新交期 | 写入新数量和新交期，保留需求行，按新数据重排 |

校验失败常见原因：

- 订单名在 Demand 中不存在 → 先写需求
- `action=insert` 但计划里已经有这张单 → 改成 `change`，或先清计划
- 删单的订单号找不到 → 检查订单号

### 2.7 物料（category=material 或 all）

```json
"materials": [
  {"name": "RAW-A", "onhand": 15, "location": "线边库"},
  {"name": "RAW-A", "po": "PO-9", "quantity": 20, "arrival": "2026-11-18T08:00:00"}
]
```

| 字段 | 说明 |
| ---- | ---- |
| `name` | 物料号 |
| `onhand` | 新现有量。同一物料有多个地点时带 `location` |
| `location` | 地点，可选 |
| `po`、`quantity`、`arrival` | 三个一起给。到货写到该采购单的结束时间 |

同一物料可以分两条：一条改现有量，一条改采购单。采购单必须已经存在。只给物料名时不改数量，只作为重排种子。

### 2.8 资源（category=resource 或 all）

```json
"resources": [
  {"name": "M-01", "start": "2026-11-16T08:00:00", "end": "2026-11-17T08:00:00", "capacity": 0}
]
```

`start` 和 `end` 都要有，且 `end` 晚于 `start`。`capacity` 不写则为 `0`（这段时间停机）。值写到该资源的产能日历；还没有日历时会建一个。只给资源名时不改日历，只作为重排种子。

## 3. 请求示例

### 3.1 插单

登录信息不写在 JSON 里，放在请求头。后面的示例只列请求体。

```http
POST /{scenario}/api/reschedule/ HTTP/1.1
Content-Type: application/json
Authorization: Bearer <API Key 或 webtoken>
```

```json
{
  "category": "order",
  "level": "auto",
  "solver": "mrp",
  "orders": [{"name": "SO-1001", "action": "insert", "item": "成品A", "quantity": 100, "due": "2026-11-20T08:00:00"}]
}
```

### 3.2 改单

```json
{
  "category": "order",
  "level": "2",
  "solver": "mrp",
  "orders": [{"name": "SO-1001", "action": "change", "quantity": 50, "due": "2026-11-22T08:00:00"}]
}
```

### 3.3 删单

```json
{
  "category": "order",
  "level": "auto",
  "orders": [{"name": "SO-1001", "action": "delete"}]
}
```

### 3.4 同一请求混合插单、删单、改单

```json
{
  "category": "order",
  "level": "auto",
  "solver": "mrp",
  "orders": [
    {"name": "SO-1001", "action": "insert", "item": "成品A", "quantity": 100, "due": "2026-11-20T08:00:00"},
    {"name": "SO-1002", "action": "delete"},
    {"name": "SO-1003", "action": "change", "quantity": 50, "due": "2026-11-22T08:00:00"}
  ]
}
```

### 3.5 物料变化

```json
{
  "category": "material",
  "level": "auto",
  "materials": [
    {"name": "RAW-A", "onhand": 15},
    {"name": "RAW-B", "po": "PO-9", "quantity": 20, "arrival": "2026-11-18T08:00:00"}
  ]
}
```

### 3.6 资源变化

```json
{
  "category": "resource",
  "level": "1",
  "resources": [{"name": "M-01", "start": "2026-11-16T08:00:00", "end": "2026-11-17T08:00:00", "capacity": 0}]
}
```

### 3.7 混合问题

```json
{
  "category": "all",
  "level": "2",
  "orders": [{"name": "SO-1002", "action": "insert", "item": "成品A", "quantity": 100, "due": "2026-11-20T08:00:00"}],
  "materials": [{"name": "RAW-A", "onhand": 15}],
  "resources": [{"name": "M-01", "start": "2026-11-16T08:00:00", "end": "2026-11-17T08:00:00", "capacity": 0}]
}
```

## 4. 响应

### 4.1 接受（HTTP 202）

```json
{
  "status": "accepted",
  "taskid": 12345,
  "scenario": "{scenario}",
  "trigger": {
    "solver": "mrp",
    "category": "order",
    "level": "auto",
    "orders": [{"name": "SO-1001", "action": "insert", "item": "成品A", "quantity": 100, "due": "2026-11-20T08:00:00"}],
    "materials": [],
    "resources": []
  },
  "status_url": "/{scenario}/execute/api/status/?id=12345",
  "log_url": "/{scenario}/execute/api/log/?id=12345"
}
```

### 4.2 冲突（HTTP 409）

已有未完成的 `runplan` 任务：

```json
{
  "status": "conflict",
  "message": "A planning task is already active",
  "taskid": 12340
}
```

### 4.3 其他错误

| HTTP | 含义                                               |
| ---- | -------------------------------------------------- |
| 400  | 参数/校验错误（`status=error`, `message=...`） |
| 401  | 未登录                                             |
| 403  | 无执行权限                                         |
| 405  | 非 POST                                            |

---
