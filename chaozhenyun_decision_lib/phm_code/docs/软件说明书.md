## 第一章 概述

### 1.1 软件名称与版本

- **软件全称**：多工况自适应工业设备控制优化系统
- **软件简称**：MACO（Multi-condition Adaptive Control Optimization）
- **版本号**：V1.0
- **开发语言**：Python
- **软件分类**：工业控制软件 / 工业互联网应用软件

### 1.2 开发背景

工业现场的旋转设备（风机、水泵、空压机、机床主轴等）长期存在两个问题。

第一个问题是**运行参数靠经验设定**。变频器开多少赫兹、导叶开多大、空压机压力带设在哪一档，多数工厂靠老师傅的经验，一旦定下就长期不动。但设备的实际负载需求在一天之内、一年四季之内都在变，固定参数意味着大部分时间运行在非最优点上，白白浪费电能。

第二个问题是**设备状态判断脱离工况**。传统监测系统给每个测点设一组固定报警阈值，可是同一台风机在满负载下振动 4.5 mm/s 完全正常，在空载下 4.5 mm/s 却已是明显异常。用一套阈值覆盖全部工况，结果必然是低负载时漏报、高负载时误报。误报多了，操作工就不再相信系统，最终系统被闲置。

本软件针对这两个问题设计。核心思路是：**先识别工况，再在该工况的上下文中做健康评估与参数寻优**。系统实时接入设备运行数据，自动辨识当前处于哪一类工况，在该工况的历史基线上评估设备健康，结合机理知识、规则推理与历史案例生成运行参数优化建议，经安全校验后与现场控制系统闭环联动，并对执行效果做统计评估，把验证有效的经验回写知识库，形成越用越准的闭环。

### 1.3 主要功能

| 序号 | 功能 | 说明 |
|---|---|---|
| 1 | 设备实时数据接入 | 支持 Modbus TCP、OPC UA、西门子 S7、MQTT 四类工业协议，采集温度、振动、电流、转速、能耗、压力、流量等信号，含五道数据清洗 |
| 2 | 状态识别与健康评估 | 工况自动辨识与稳态判定；按工况归一化的健康评估，输出分项指标、总健康分、疑似故障模式、退化趋势与剩余可用时间 |
| 3 | 运行参数优化建议 | 代理模型 + 三种寻优算法，融合规则推理与历史案例，输出带完整证据链的可执行参数调整建议 |
| 4 | 控制系统闭环联动 | 七道安全校验后写入 PLC / SCADA / DCS，写后回读校验，失败整体回滚，全过程审计留痕 |
| 5 | 执行效果反馈学习 | 下发前后双窗口统计检验，折算奖励，回写代理模型、规则可信度、案例库与工况档案 |

### 1.4 技术特点

**特点一：工况归一化的评估基准。** 系统为每一个 (设备, 工况, 特征) 三元组独立维护正常基线，健康判断依据是"当前值相对本工况基线偏离了多少个标准差"，而不是与固定阈值比较。这从根本上解决了固定阈值在多工况场景下必然误报或漏报的问题。

**特点二：工况库自增长。** 系统不要求人工预先定义有哪些工况。运行中遇到与已知工况差异超过新颖度阈值的运行点，自动建档为新工况并开始积累基线。工况库设有容量上限与低频淘汰机制，不会无限膨胀。

**特点三：知识与数据双驱动。** 建议不是黑箱模型的单一输出，而是三路候选的择优结果：知识规则给出方向性动作与硬性禁令，案例库给出历史上验证有效的参数，代理模型给出定量寻优结果。每条建议都附带可逐条展开的证据链，操作工能看懂"为什么建议把频率从 45Hz 调到 43.6Hz"。

**特点四：安全优先的写通道。** 优化算法只管目标最优，不天然懂得"这个阀门每分钟只能开 2%"。系统把这类工程常识固化为七道不可绕过的安全检查，并采用 fail-closed 原则：任何判定所需信息缺失时一律拒绝而非放行。

**特点五：闭环可验证。** 每一次参数调整都会在设定的观测窗后自动评估效果，用 Welch t 检验判定变化是否显著，避免把噪声当成效果。只有通过显著性检验且奖励为正的调整，其经验才会被写回知识库供后续复用。

**特点六：全链路可追溯。** 从采集帧到最终写值，全链路携带同一个链路标识；审计账本采用链式哈希，任何记录被篡改或缺失都能检出。给定任意一次写值，可完整回溯它依据的原始数据、工况判定、健康评估与知识证据。

### 2.1 硬件环境

### 2.2 软件环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / Windows Server 2016 及以上；或主流 Linux 发行版 |

## 第三章 系统架构

### 3.1 分层结构

系统采用八层结构，层间通过事件总线解耦，每一层都可独立替换与独立测试。

```
┌─────────────────────────────────────────────────────────┐
│  接口层 api        REST 接口 / 命令行                    │
├─────────────────────────────────────────────────────────┤
│  引擎 engine       装配、编排、留痕                       │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│ 反馈层    │ 控制层    │ 优化层    │ 知识层    │  场景层     │
│ feedback │ control  │optimiz.. │knowledge │  scenario   │
├──────────┴──────────┴──────────┴──────────┴─────────────┤
│  健康层 health     基线 / 异常 / 故障模式 / 趋势          │
├─────────────────────────────────────────────────────────┤
│  工况层 condition  工况库 / 归属判定 / 稳态判定           │
├─────────────────────────────────────────────────────────┤
│  特征层 features   时域 / 频域 / 热电能效                 │
├─────────────────────────────────────────────────────────┤
│  接入层 acquisition 驱动 / 缓冲 / 清洗                    │
├─────────────────────────────────────────────────────────┤
│  内核层 core       类型 / 配置 / 总线 / 调度 / 审计       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 主处理流程

一次完整决策由九个阶段串联而成：

```
  ①采集 → ②清洗 → ③特征提取 → ④工况识别 → ⑤健康评估
     → ⑥知识推理与参数寻优 → ⑦安全校验 → ⑧控制下发与回读
        → ⑨延时效果评估与知识回写
                    ↑                              │
                    └──────────────────────────────┘
                          经验回流，下一轮更准
```

其中第 ⑨ 阶段是与普通分析软件的分界线：普通软件在第 ⑥ 步给出建议就结束了，本系统会在参数生效若干分钟后自动回来核对效果，并把核对结论写回知识库。

### 3.3 关键数据对象

| 对象 | 作用 |
|---|---|
| `SampleFrame` 采集帧 | 同一时刻同一设备的一组测点值，是链路标识的起点 |
| `FeatureVector` 特征向量 | 时域、频域、热电能效特征的统一载体 |
| `ConditionSnapshot` 工况快照 | 当前工况编号、置信度、稳定性、已持续时长 |
| `HealthReport` 健康报告 | 分项指标、总分、等级、疑似故障模式、趋势、剩余可用时间 |
| `OptimizationAdvice` 优化建议 | 参数变更清单、预期收益、置信度、风险等级、证据链 |
| `ControlCommand` 控制指令 | 唯一允许触达现场的写载体，带完整状态机 |
| `EffectEvaluation` 效果评估 | 前后对比、显著性检验、标量奖励、评估结论 |
| `ExperienceCase` 经验案例 | 一次完整闭环的浓缩记录，回写知识库供复用 |

## 第四章 功能一：设备实时数据接入

### 4.1 支持的信号类型

系统按信号语义划分处理通路，不同类别走不同的特征提取路径。

| 类别 | 典型测点 | 处理方式 |
|---|---|---|
| 温度 | 轴承温度、电机温度、排气温度、环境温度 | 稳态统计 + 温升计算 |
| 振动 | 驱动端振动、非驱动端振动 | 时域特征 + 频谱 + 包络谱 |
| 电流 | 三相电流 | 稳态统计 + 三相不平衡度 |
| 转速 | 主轴转速 | 稳态统计 + 转速比 |
| 能耗 | 有功功率、累计电能 | 稳态统计 + 单位产出能耗 |
| 压力/流量 | 出口压力、储气罐压力、风量、水量 | 稳态统计 + 能效比 |
| 设定值 | 变频器频率设定、导叶开度设定、压力带设定 | 只读监视，不参与健康评估 |

### 4.2 支持的通信协议

**Modbus TCP**。面向 PLC 与智能仪表最常见的协议。系统自行实现 MBAP 报文封装与 PDU 编解码，支持线圈、离散输入、保持寄存器、输入寄存器四个功能码区，支持 int16 / uint16 / int32 / uint32 / float32 / int64 / float64 七种数据类型以及字节序与字序配置。地址写法示例：

```
3:40001:float32:big     保持寄存器 40001，32 位浮点，大端
4:30010:int16           输入寄存器 30010，16 位有符号整数
1:00005:bool            线圈 5
```

系统会自动把地址相邻、类型一致的测点合并成一次批量读，单次请求最多 125 个寄存器，显著降低通信次数与 PLC 负担。

**OPC UA**。面向 SCADA、DCS 与智能网关。地址采用标准 NodeId 写法：

```
ns=2;s=Line1.Fan01.BearingTemp
ns=3;i=1057
```

系统同时支持轮询读（Read Service）与订阅推送（Subscription + MonitoredItem）两种取数方式。关键点位采用订阅推送可显著降低网络负载与响应延迟。

**西门子 S7**。面向 S7-300/400/1200/1500 系列 PLC，报文在 ISO-on-TCP（RFC1006）之上承载 S7 PDU，系统自行完成 TPKT、COTP、S7 三层封装。地址沿用西门子习惯写法：

```
DB100.DBD0:real     DB100 块偏移 0，双字浮点
DB100.DBW10:int     DB100 块偏移 10，字整型
DB100.DBX4.2:bool   DB100 块偏移 4 的第 2 位
MD20:real           存储器双字浮点
```

**MQTT**。面向 IIoT 网关、边缘采集盒与无线传感器。与前三种"主动轮询"不同，MQTT 是"被动订阅"，系统内部维护最新值缓存，并按超时阈值判定数据是否陈旧。地址写法支持从 JSON 消息中提取字段：

```
plant/line1/fan01/temp                        整条消息即为数值
plant/line1/fan01/telemetry#bearing_t         取 JSON 字段
plant/line1/fan01/telemetry#sensors.0.value   支持嵌套路径与数组下标
```

**仿真驱动**。系统内置设备仿真模型，接口与真实驱动完全一致，用于离线联调、算法验证与演示培训。仿真设备会真实响应下发的控制指令并改变后续输出，因此可以在没有任何现场设备的条件下验证整个闭环是否有效。

### 4.3 数据质量判定

每个采样值都带质量标记，语义参照 OPC UA StatusCode 简化模型：

| 标记 | 含义 | 是否参与后续计算 |
|---|---|---|
| 良好 | 正常数据 | 是 |
| 存疑 | 疑似异常但未确认 | 是 |
| 替代值 | 被清洗规则替换过 | 是 |
| 坏值 | 明确无效 | 否 |
| 陈旧 | 超过时限未更新 | 否 |
| 超量程 | 超出变送器量程 | 否 |
| 通信中断 | 读取失败 | 否 |

### 4.4 数据清洗

现场数据必然带噪：传感器掉线会出现死值，接线松动会出现尖峰，变送器漂移会越量程，网络抖动会造成时标错乱。若不清洗直接进入健康评估，会产生大量误报。系统在链路最前端执行五道清洗，每道可独立开关。

**第一道，量程校验。** 超出测点定义量程的值直接判为超量程，不进入后续计算。

**第二道，死值检测。** 连续 N 拍（默认 30 拍）数值完全不变，判定传感器僵死。判定阈值取量程的百万分之一，兼容不同量纲。设定值与开关量类测点自动跳过本道检查——它们本就长期恒定，检查必然误伤。

**第三道，尖峰剔除。** 相对最近窗口中位数的偏离超过 K 倍稳健标准差（默认 5 倍）判为跳变。采用中位数与 MAD 而非均值与标准差，是因为均值本身会被尖峰污染。命中后可选择替换为中位数或仅标记为存疑。

**第四道，缺口插补。** 短缺口（默认不超过 3 点）做线性插补，长缺口保留为坏值不臆造数据。

**第五道，时标对齐。** 帧内偏离帧时标过大的测点统一到帧时标，容差按帧内时标分布自适应，不用固定值。

每一次清洗动作都会记入清洗报告，包含测点、命中规则、原值、修正值与说明，可完整回溯，不存在静默修改数据的情况。

### 4.5 时序缓冲

系统在内存中维护每个测点的近期时序，为三类下游供数：特征提取取最近 N 秒算特征，稳态判定取窗口内变异系数，效果评估取控制下发前后两段等长窗口做对比。缓冲按时长而非条数裁剪，因为现场采样周期可能动态变化。

## 第五章 功能二：设备状态识别与健康评估

### 5.1 工况识别

**为什么必须先识别工况。** 同一台设备在不同负载下，各测点的正常范围完全不同。若用一套固定阈值判断，低负载时漏报、高负载时误报。因此系统先回答"现在是哪个工况"，再在该工况的上下文中做后续判断。

**第一步，签名提取。** 从特征向量中取出决定工况的少数几个量构成工况签名。默认取负载率、转速比、电流负载率、平均温度，各场景可自定义。

**第二步，归属判定。** 用马氏距离把签名匹配到工况库中最近的工况。距离超过新颖度阈值（默认 3.5）时，判定为新工况并自动建档。

系统对小样本情形做了专门处理：新建工况在样本数不足 3 条时协方差不可信，改用相对欧氏距离并折算到同一量纲；同时对各维方差设置了最小相对标准差下限（3%）。没有这两项处理，小样本会把方差压到接近零，马氏距离随之爆炸，结果是每一拍都被判成新工况，工况库瞬间失控。

**第三步，稳态判定。** 看签名在时间窗内的波动程度：

| 判定结果 | 条件 | 是否允许优化 |
|---|---|---|
| 稳态 | 变异系数低于阈值，且观测充分 | 允许 |
| 过渡 | 变异系数超过阈值 | 不允许 |
| 启机 | 波动大且负载上行 | 不允许 |
| 停机 | 波动大且负载下行 | 不允许 |
| 空载 | 负载低于 5% | 不允许 |

观测充分性有两条判据：持续时长达到下限，或采样条数达到下限，满足其一即可。只卡时长会让高频采集场景等待过久，只卡条数会让低频场景误判，两者取其一是工程上的折中。

**去抖动。** 工况切换需要连续 N 次（默认 3 次）判定为同一新工况才确认，避免边界处来回抖动。

### 5.2 健康基线

系统为每一个 (设备, 工况, 特征) 三元组独立维护正常基线，内容包括中位数、MAD、上下限与 EWMA 控制图状态。基线采用稳健统计量而非均值方差，抗离群点能力更强。

基线只在设备被判定为健康且工况稳定时才学习，劣化期间不学。否则系统会把故障状态当成正常，逐渐"习惯"设备的劣化，最终什么都报不出来。

### 5.3 健康指标

系统计算四个维度的分项指标，每项都折算为 0~1 的健康分。

| 维度 | 指标 | 默认权重 |
|---|---|---|
| 振动 | 各测点有效值、峭度、峰值因子 | 0.35 |
| 温度 | 最高温度、温升、绝对红线 | 0.25 |
| 电流 | 电流负载率、三相不平衡度 | 0.20 |
| 能效 | 单位产出能耗、单位转速功率 | 0.20 |

偏离量到健康分的映射采用平滑函数：偏离为零时得 1 分，偏离达到容差时约 0.5 分，超过容差后加速下降。这样既不会因微小波动就报警，也不会在明显异常时还给出高分。

温度维度额外设有绝对红线：超过铭牌报警值直接判危险等级，不依赖基线。这是因为温度红线是设备本身的物理限制，与工况无关。

三相不平衡度采用固定判据（国标一般要求低于 5%），也不依赖基线。

### 5.4 异常检测

系统采用双通道异常检测。

**EWMA 控制图。** 对偏离量做指数加权移动平均，检出连续小幅偏移。单次超限可能是噪声，但连续同向偏移几乎一定是真实变化。

**偏离阈值。** 单次偏离超过容差的 1.0 倍记预警、1.5 倍记报警。

两个通道都会把命中项写入异常清单，附带测点名、偏离倍数与当前值。

### 5.5 故障模式定位

系统内置九条通用旋转机械故障判据，基于特征频率与偏离度而非绝对值：

| 疑似模式 | 判据 |
|---|---|
| 转子不平衡 | 1 倍频突出、2 倍频不高 |
| 联轴器不对中 | 2 倍频显著，伴随 1 倍频升高 |
| 结构松动 | 谱熵与峰值因子同时升高 |
| 轴承外圈异常 | 包络谱外圈通过频率处峰值突出 |
| 轴承内圈异常 | 包络谱内圈通过频率处峰值突出 |
| 滚动体异常 | 包络谱滚动体频率处峰值突出 |
| 过热 | 温度显著高于本工况基线 |
| 过载 | 电流偏高且负载接近额定 |
| 结垢积灰 | 能效下降伴随温升 |

轴承四大特征频率（外圈 BPFO、内圈 BPFI、滚动体 BSF、保持架 FTF）由轴承几何参数与实测转速直接计算得出，属于机理知识而非数据学习结果。在包络谱上定点核对这些频率，比泛泛的"振动超标"判断精确得多，能显著降低误报。

### 5.6 融合评级与趋势

**融合。** 各分项按权重加权，同时对最差项施加 30% 的额外权重。纯加权平均会让"九项正常、一项严重"被平均成"整体尚可"，加入最差项拖拽后，单一致命项不会被掩盖。

**等级。** 总分映射为四级：健康（≥0.85）、关注（≥0.65）、劣化（≥0.40）、危险（<0.40）。

**趋势。** 对健康分历史做最小二乘回归，得到退化速率（健康分/天）。趋势分为好转、平稳、恶化、波动四类。当波动大而拟合优度低时判为波动而非恶化，避免把噪声当成劣化。

**剩余可用时间。** 恶化趋势下，按当前退化速率外推到危险阈值 0.40 所需的时间。这是一个粗略的运维提示，不是精确的寿命预测，界面上应如实标注其性质。

## 第六章 功能三：运行参数优化建议

### 6.1 决策依据的四路输入

| 输入 | 作用 |
|---|---|
| 工况快照 | 决定在哪个上下文优化，以及是否允许优化 |
| 健康报告 | 决定目标偏向：劣化时保设备优先，健康时省能优先 |
| 知识推理 | 规则给出方向性动作与硬性禁令，案例给出历史有效参数 |
| 代理模型 | 在参数邻域内做定量寻优 |

### 6.2 知识推理

系统采用前向链推理机，规则形式为 IF-THEN，带优先级与可信度。规则条件使用受限表达式描述，只允许数字、字符串、比较符、and/or/not、括号与事实名，其它记号一律拒绝。这样既保证现场工程师可以直接编辑规则文件，又杜绝了通过规则配置执行任意代码的风险。

内置的十条通用规则包含四条安全禁令：

- 健康度低于 0.40 时禁止自动调参（应先检修）
- 工况非稳态时禁止调参（等待稳态）
- 首次进入某工况时禁止调参（先积累基线）
- 三相不平衡超标时禁止升载

以及六条方向性建议，覆盖温度接近红线时优先降载、振动偏高时降速、轴承特征频率突出时限速报修、能效偏低时触发寻优等场景。

规则可信度会随反馈学习动态调整：被证明有效的规则可信度上升，被证明无效的下降。

### 6.3 约束模型

约束分硬软两类。硬约束不可违反，违反即判定当前运行点不可行，直接放弃本轮优化；软约束可违反但计入罚分，参与寻优目标。

内置的六条通用约束包括轴承温度上限 85℃、振动烈度上限 11.2 mm/s（ISO 20816 C 区上限）、电流不超额定 105%、转速在额定值 30%~102% 之间等。各场景可追加专属约束。

### 6.4 案例复用

案例库采用基于案例的推理（CBR）方法，四个步骤：

**检索。** 按工况签名相似度检索历史案例。同工况的案例给予 15% 的相似度加成；被验证有效的案例按可信度加权；未被采纳的案例相似度打六折。

**复用。** 把 top-k 案例的参数按相似度与可信度加权融合成一组建议参数。

**修正。** 按实际执行效果更新案例可信度，有效则上调，无效则下调。

**保留。** 新的闭环结果入库成为新案例。案例库设有容量上限，超限时淘汰可信度最低且最久未复用的案例。

### 6.5 代理模型

现场不可能为了优化而反复试错，因此必须靠历史运行数据建模，在模型上搜索，只把最终少数几个候选拿到现场验证。

系统采用加权最近邻结合局部线性的轻量代理模型，而不是神经网络。原因是现场样本通常只有几十到几百条，复杂模型必然过拟合。本模型在样本少时退化为最近邻，样本多时自动接近局部线性回归，且训练成本可忽略。

模型同时输出预测置信度，由邻域内有效样本权重之和决定：外推到无样本区域时置信度趋近零，上层据此拒绝采纳该建议。这是防止模型在没见过的区域胡乱外推的关键。

### 6.6 寻优算法

系统提供三种算法，可配置或自动选择。

| 算法 | 适用场景 |
|---|---|
| 贝叶斯优化 | 样本少、采样成本高时，靠置信上界平衡探索与利用 |
| 粒子群优化 | 连续参数空间，收敛快，适合日常小步调优 |
| NSGA-II | 多目标冲突时，输出帕累托前沿供人选点 |

自动选择规则：目标数大于等于 2 时用 NSGA-II；样本少于 20 条时用贝叶斯优化；其余用粒子群。

关于 NSGA-II 的价值：当"省电"与"保产量"直接冲突时，单目标加权会把取舍偷偷藏进权重里；帕累托前沿把取舍摊开给人看，由人来选点。这更符合工业决策的实际习惯。

所有算法都使用固定随机种子，保证同样输入必得同样建议——工业场景要求决策可复现、可追溯。

### 6.7 邻域限制

这是工业场景与实验室优化的关键差别：**不允许一次跳到远端最优点，必须小步走、边走边验证。**

系统以当前工作点为中心划出允许搜索的邻域，邻域大小由三个因素共同决定：配置的最大相对变化比例、参数自身的单次最大变化量、以及健康度（健康度越低邻域越小）。规则也可以临时收紧邻域，例如"退化趋势明显时只做小幅调整"。

### 6.8 建议产出

每条建议包含：

- **参数变更清单**：参数名、当前值、建议值、变化量、绑定的写入点
- **预期收益**：各优化目标的相对改善量
- **综合置信度**：低于阈值时降级为仅供参考，不进入控制链路
- **风险等级**：提示、预警、报警、故障
- **证据链**：每条证据标明类型（规则推理 / 历史案例 / 代理模型 / 约束边界 / 统计特征 / 机理计算）、来源标识、陈述内容与可信度
- **自然语言说明**：面向操作工的完整叙述

说明的典型形式：

> 当前处于高负载工况（稳态，已持续 42 分钟），健康度 0.91（健康）。依据代理模型寻优建议调整：变频器频率 45.00Hz → 43.60Hz（-1.40）。预计效果：单位风量能耗预计下降 8.4%、风量预计下降 3.1%。规则提示：风量存在富余，降频可按三次方律省电。

单次建议最多调整 3 个参数，按变化幅度取前 3 项。一次不动太多变量，是为了让效果评估能够归因。

## 第七章 功能四：与 PLC / SCADA / DCS 闭环联动

### 7.1 读写分离

系统把写通道与读通道分开建模。原因是读和写的风险等级完全不同：读错一个点只是数据不准，写错一个点可能导致停机甚至事故。

写通道强制具备四项能力：

1. **写前锁定**——确认目标点当前处于远程/自动模式且允许上位机写入
2. **原值留存**——写前记录原值，任何一步失败都能原路回滚
3. **写后回读**——写完立即读回，比对是否真的生效
4. **写审计**——每次写值留痕，包含谁、何时、把什么改成了什么

### 7.2 三类适配器

**PLC 适配器。** 直连 PLC 寄存器（Modbus 或 S7 通道）。典型用法是把"风机变频器频率设定"直接写到 PLC 保持寄存器，PLC 内部的 PID 与联锁逻辑保持不变。**系统只改设定值，不接管调节回路**——这是与现场控制系统安全共处的基本原则。

**DCS 适配器。** 一般经 OPC UA 通道。DCS 场景额外要求写入前确认回路处于串级或远程设定状态，否则设定值会被就地控制器覆盖，形成"写进去但不起作用"的假象。

**SCADA 适配器。** 通过 SCADA 平台的点表接口间接下发。SCADA 通常有自己的操作权限与命令确认机制，因此写操作被建模为"提交命令 → 等待确认 → 回读点值"三步。

### 7.3 七道安全检查

任何写向现场的指令都必须先通过安全门。七道检查按代价从低到高排列，任一不过立即驳回。

| 序号 | 检查项 | 驳回条件 |
|---|---|---|
| 1 | 模式检查 | 当前控制模式不允许写 |
| 2 | 建议有效性 | 建议为空或置信度低于阈值 |
| 3 | 健康闸门 | 设备健康等级达到禁止自动调参的门限 |
| 4 | 点位检查 | 目标点不存在、不可写或不在量程内 |
| 5 | 限幅限速 | 超出参数定义域、单次变化量或相对变化比例 |
| 6 | 互锁检查 | 检修挂牌、急停动作、通信质量差、温度超红线 |
| 7 | 频次限流 | 距上次下发不足最小间隔，或本小时次数达上限 |

设计原则是 **fail-closed**：任何判定所需信息缺失时一律拒绝而非放行。例如无法读取模式点时，按"不允许写入"处理。

### 7.4 四种控制模式

| 模式 | 行为 |
|---|---|
| 只读观察 | 只采集与评估，不产生任何写操作 |
| 建议模式 | 生成建议并推送给操作工，由人工在 HMI 上手动执行 |
| 半自动 | 生成指令并进入待审批队列，人工确认后由系统下发 |
| 自主闭环 | 通过安全校验后自动下发 |

现场投运的推荐路径是：只读观察运行两周积累基线 → 建议模式运行一个月建立信任 → 半自动运行一段时间 → 视情况开放自主闭环。这个顺序不建议跳过。

### 7.5 执行与回滚

指令执行采用"分步下发 + 逐点回读 + 失败整体回滚"策略。工业场景不接受写了一半的状态，因此任一点位失败都会触发已写入点位的逆序回滚。回滚本身若失败，会作为最高优先级告警上报，因为此时现场可能处于不一致状态，必须人工干预。

### 7.6 闭环状态机

闭环有七个阶段，显式化的价值在于任何一次调整都能回答"现在走到哪一步、卡在谁那里、失败在哪个阶段"：

```
空闲 → 安全校验 → （待审批）→ 下发中 → 回读验证 → 学习中 → 完成
```

指令本身另有独立的生命周期状态：草拟、已校验、已驳回、待审批、下发中、已下发、回读确认、下发失败、已回滚、已评估。

## 第八章 功能五：执行效果反馈学习

### 8.1 为什么必须有这一环

这是让系统"越用越准"的最后一环，也是与"只会给建议的分析软件"的根本区别。每一次调整都要回答三个问题：到底有没有效？这次经验值多少分？学到的东西写回哪里？

### 8.2 效果评估

**双窗口对比。** 取下发前一段窗口与参数生效后一段等长窗口，逐指标对比。中间留出参数生效等待期（默认 120 秒），因为一阶惯性环节不会瞬间响应。

**观测指标。** 系统按设备测点表自动生成观测指标集，典型包括有功功率（越低越好）、产出流量（越高越好）、振动（越低越好）、温度（越低越好）、电流（越低越好）。

**显著性检验。** 只看均值差会被工况漂移骗过去，因此必须做统计检验。系统采用 Welch t 检验（不假设方差齐性），|t| 超过阈值（默认 2.0）才认定变化显著。变化幅度大但方差更大的，不算有效。

### 8.3 奖励计算

把多指标变化折算成一个标量奖励，规则有三条：

1. **按期望方向定符号**——"越低越好"的指标下降记正分，上升记负分
2. **未通过显著性检验的变化打折**（乘 0.35），通过的加成（乘 1.2）——避免把噪声当成效果
3. **负向变化施加惩罚系数**（默认 1.5 倍）——对"省了电但设备更抖"这类拆东墙补西墙的调整加重扣分

奖励范围裁剪到 [-1, 1]，正值表示本次调整整体有益。

系统同时输出人类可读的评估结论，形式如：

> 本次调整整体有效（奖励 +0.127，3 项通过显著性检验）：有功功率下降 8.6%（显著）；风量下降 2.9%（显著）；驱动端振动下降 1.2%（不显著）。

### 8.4 四个学习去处

评估结论会分发到四个地方：

| 去处 | 学到什么 |
|---|---|
| 代理模型 | 增加一条真实运行样本，下次预测更准 |
| 规则可信度 | 触发本次调整的规则，有效则可信度上调，无效则下调 |
| 案例库 | 本次闭环浓缩为一条经验案例入库，供同工况复用 |
| 工况档案 | 更新该工况下已知的最优参数组合 |

### 8.5 在线学习

系统内置线性上下文老虎机（LinUCB 简化版），用于在若干候选调整方向之间做在线权衡。它不替代代理模型，而是解决"同一工况下多种调法都说得通，先试哪个"的问题。

上下文向量由工况签名与健康度构成，动作臂由各参数的调整方向组合抽象而成（如"频率降、导叶升"）。探索比例可配置，保证工业现场不会出现无节制试错。

### 8.6 预测误差校准

系统会记录"预测收益"与"实际收益"之差。这个差值是代理模型可信度的直接度量：长期偏差大说明模型与现实脱节，需要重新积累样本或调整模型带宽。

## 第九章 多场景适配

### 9.1 场景配置的构成

一份场景配置把四样东西打包在一起：

- 测点表：采什么、从哪采、量程多少
- 可调参数表：能调什么、调多大、写到哪个点
- 优化目标与权重：这个场景优先省电还是优先保产
- 场景专属规则与约束：这个场景特有的工程常识

**换一个应用场景只需换一份场景配置，内核代码完全不动**——这是"多场景适配"在工程上的具体含义。

### 9.2 内置场景

**变频风机节能场景。** 以单位风量能耗最低为主目标，兼顾风量满足与轴承健康。核心优化逻辑是用变频替代导叶节流。依据相似定律，转速降 10% 流量只降 10%，功率却降约 27%，因此在风量有余量时降速能显著省电。专属约束包括最低风量保障与变频器最低频率（低于 30Hz 电机散热不足）。

**空压机压力带优化场景。** 在保证末端用气压力的前提下压低卸载压力，同时控制加卸载频次。这里的优化结构与风机完全不同：压力带设得太窄会频繁加卸载，空载能耗白白浪费；设得太宽则压力波动大影响用气。专属约束包括最低供气压力、压力带最小宽度 0.08MPa、排气温度上限 105℃。

**循环水泵机组优化场景。** 多台泵并联运行时，在满足总流量的前提下选择开机台数与各台转速的组合，使机组总能耗最低。专属约束包括汽蚀余量与最小连续流量。

**数控机床主轴工艺参数优化场景。** 在保证加工表面质量与刀具寿命的前提下，优化主轴转速与进给量，缩短单件工时。与流体机械不同，此场景的核心约束来自工艺而非能耗，专属约束包括主轴负载上限与颤振抑制。

### 9.3 新增场景的步骤

1. 定义测点表：列出该场景需要采集的信号及其地址、量程、采样周期
2. 定义可调参数表：列出允许系统调整的参数及其定义域、单次最大变化量、绑定写入点
3. 定义优化目标与权重
4. 编写场景专属规则与约束（可选，通用规则已覆盖大部分安全场景）
5. 注册到场景表

全过程不涉及内核代码修改。

```bash
# 1. 解压软件包
unzip maco-adaptive-control.zip
cd maco-adaptive-control

# 2. 创建虚拟环境（推荐）
python -m venv .venv

pip install -r requirements.txt

# 4. 验证安装
python -m maco.cli scenarios
```

### 10.2 快速验证

在没有任何现场设备的情况下，运行全仿真演示验证系统完整功能：

```bash
python examples/run_demo.py
```

演示脚本会依次展示数据接入、工况识别、健康评估、优化建议、闭环下发、效果评估与故障注入七个环节。

### 10.3 现场部署

**第一步，编写配置文件** `config/system.json`：

```json
{
  "system": { "instance_id": "plant-a-node-1", "log_level": "INFO" },
  "control": { "mode": "observe" },
  "devices": [
    {
      "device_id": "FAN-01",
      "profile": "fan",
      "scenario": "fan_vfd",
      "driver": {
        "type": "modbus_tcp",
        "options": { "host": "10.1.2.30", "port": 502, "unit_id": 1 }
      },
      "control": {
        "type": "plc",
        "options": { "mode_point_id": "remote_mode" }
      }
    }
  ]
}
```

**第二步，以只读观察模式启动**，运行两周积累基线：

```bash
python -m maco.cli run --config config/system.json --interval 30
```

**第三步，逐步放开控制权限**。确认基线稳定、建议合理后，把 `control.mode` 依次改为 `advisory`、`supervised`、`autonomous`。

### 10.4 启动接口服务

```bash
export MACO_API_TOKEN=<你的令牌>
python -m maco.cli serve --config config/system.json --host 127.0.0.1 --port 8780
```

令牌通过环境变量注入，不写入配置文件，不落日志。

### 11.2 日常操作流程

**查看设备状态。** 调用状态接口或命令行 `status`，重点关注健康等级、趋势方向与异常清单。

**处理优化建议。** 建议模式下，系统生成的建议会出现在建议列表中。操作工需要看三件事：建议内容（改什么、改多少）、预期收益、证据链。确认合理后在 HMI 上手动执行；若不合理，可在系统中标记驳回，驳回记录会参与规则可信度调整。

**审批待下发指令。** 半自动模式下，通过安全校验的指令进入待审批队列。审批界面会显示指令内容、安全门备注与风险等级。审批通过后系统自动下发；驳回需填写原因。

**查看效果评估。** 参数调整后，系统会在观测窗结束后自动给出效果评估。重点看奖励值与显著性判定，不显著的变化不应作为决策依据。

**追溯一次调整。** 拿到链路标识后调用追溯接口，可以看到这次调整依据的原始数据、工况判定、健康评估、知识证据、安全裁定、执行结果与效果评估的完整链条。

### 11.3 参数调整建议

| 配置项 | 含义 | 调整建议 |
|---|---|---|
| `acquisition.poll_interval_ms` | 采集周期 | 振动类建议 1000ms，其余可放宽到 5000ms |
| `condition.novelty_threshold` | 新工况判定阈值 | 工况库增长过快就调大，工况区分不开就调小 |
| `condition.steady_min_dwell_s` | 稳态最短持续时间 | 设备惯性大的场景调大 |
| `health.weights` | 健康维度权重 | 按设备关键失效模式调整 |
| `control.max_delta_ratio` | 单次最大相对变化 | 投运初期建议 0.05，稳定后可放宽到 0.10 |
| `control.min_dispatch_interval_s` | 最小下发间隔 | 应大于参数生效时间与观测窗之和 |
| `optimization.min_confidence` | 建议置信度阈值 | 投运初期建议 0.7，样本充足后可降到 0.55 |

## 第十三章 安全机制

### 13.1 控制安全

- 七道写前安全检查，fail-closed 原则
- 四道内置互锁：检修挂牌、急停动作、通信质量差、温度超红线
- 单次变化量与变化率双重限幅
- 下发频次限流：最小间隔与每小时次数上限
- 失败整体回滚，回滚失败升级为最高优先级告警
- 只改设定值，不接管现场 PID 与联锁逻辑

### 13.2 数据安全

- 密钥类配置（令牌、口令、密钥）在配置导出与日志输出中一律脱敏
- 访问令牌通过环境变量注入，不写入配置文件
- HTTP 服务默认仅绑定回环地址
- 日志过滤器对疑似敏感值做掩码

### 13.3 追溯安全

- 全链路统一链路标识，任意一次写值可回溯到原始数据
- 审计账本采用链式哈希：每条记录含前序哈希，任何篡改或缺失都能检出
- 审计账本只写不改，更正以新增"更正记录"的方式表达
- 提供账本完整性校验命令

### 13.4 运行安全

- 单个订阅者异常不影响其它订阅者，异常转为系统错误事件集中监控
- 单台设备通信中断不拖垮整个采集循环
- 单个调度任务失败不影响调度器与其它任务
- 通信失败按指数退避重试，重试耗尽后标记数据质量而非抛出异常
- 规则条件使用受限表达式求值，杜绝通过配置执行任意代码

## 第十四章 常见问题

**问：系统上线后一直不给建议，是什么原因？**

答：按以下顺序排查。第一，看工况稳定性是否为"稳态"，非稳态时系统主动不给建议。第二，看基线是否建立完成，界面上会显示"基线学习中"。第三，看代理模型样本数是否达到最小要求（默认 12 条）。第四，看健康度是否低于禁止调参门限。这四种情况都是设计上的主动抑制，不是故障。

**问：工况数量增长很快，正常吗？**

答：投运初期工况库快速增长是正常的，系统在探索设备的运行空间。若持续增长不收敛，说明新颖度阈值偏小，可调大 `condition.novelty_threshold`。工况库设有容量上限与低频淘汰，不会无限膨胀。

**问：建议被安全门驳回怎么办？**

答：驳回都会附带规则编号与原因。SG-03 是置信度不足，需要更多样本；SG-04 是健康度不达标，应先处理设备问题；SG-11/SG-12 是变化幅度超限，说明算法想做大幅调整而安全策略不允许，可评估是否放宽限幅；SG-13 是频次限流，等待即可。

**问：效果评估显示"不显著"，说明建议没用吗？**

答：不一定。不显著意味着这次变化的幅度相对于数据本身的波动不够大，无法在统计上确认。可能是调整幅度太小，也可能是观测窗太短。可以适当延长观测窗或放宽单次限幅后再观察。

**问：可以直接开自主闭环模式吗？**

答：不建议。推荐路径是只读观察两周 → 建议模式一个月 → 半自动一段时间 → 自主闭环。跳过前面的阶段，系统既没有足够的基线，也没有建立起操作工的信任，出一次误动作就再也推不下去了。

**问：系统会不会和现场 PLC 抢控制权？**

答：不会。系统只写设定值，不接管调节回路。PLC 内部的 PID、联锁与保护逻辑完全保持原样。任何时候现场把回路切到手动或就地，系统的写操作都会被安全门以"不在远程模式"拒绝。
