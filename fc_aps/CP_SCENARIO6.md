# 场景6：三天内尽量多排

默认使用 `plan.solver=cp`、`cp.planning_mode=throughput`、`cp.horizon_days=3`、`cp.material_mode=selfmade`。窗口从案例的 `currentdate` 开始，当前数据为 **2026-09-10 08:00 至 2026-09-13 08:00**。

主要目标是窗口内完成的生产批次数最多；同等批次数下优先缩短总完工时间。不再要求所有 MRP 批次都进入排程。批次数量保持 MRP 已确定的值，联产物料平衡不变；同一工单树中的工序一起选择。设备、模具、人员、出勤人数、自制件供应和锁定工单仍是约束。外购料供应不限，不因有限库存阻止排程；自制件按物料类别“自制”检查初始库存、上游产出时间和可用数量。未填写类别时根据制造工序的产出关系识别自制件。跨班次时只在共同开放的工作时段内累计加工时间。

MRP 中没有标准工时且没有受限资源的逻辑联产工序保留为瞬时工序：开始时间等于结束时间，不占用产能，但其产出仍参与自制件供料和上下游先后约束。若工序使用受限资源，即使缺少工时也至少占用 1 秒，避免产生免费的有限产能。

未入选的拟议生产计划从本次结果中移除，需求原始数量不变，未满足部分保留待排。无约束资源（包括无限容量资源）和未配置资源的生产批次同样进入 CP 候选池，保留加工时间、工序/地点日历及物料关系，可以并行加工；只有有限且启用容量约束的资源占用产能。拟议出货数量按入选生产和真实库存重新限制，已锁定计划不变。

配置支持环境变量 `CP_PLANNING_MODE=throughput` 和 `CP_HORIZON_DAYS=3`。默认 `auto` 会对 `FC_OP_` 案例启用该目标；`all` 可显式恢复全量排程。该模式下主要目标优先于 `cp.objective_method` 的其他优化方法。`CP_MATERIAL_MODE=selfmade` 启用当前供应口径，`all` 保留通用库存约束口径。`CP_TIME_LIMIT_SECONDS` 默认 60 秒，`CP_WORKERS` 默认 8；到时使用已找到的可行结果，不保证已证明最优。未找到可行解时不应用 CP 结果。

转换脚本和场景 JSON 均已设置上述默认参数。Django 执行入口读取参数并在调用后恢复环境变量。在线排程仍应通过现有的“运行计划”入口执行。

CP 回归包括三天容量下选择部分批次、锁定容量、物料依赖、未入选上游不供料、部分出货、无约束上游供料、无约束批次并行和超出窗口待排、无限容量资源配合工序日历、跨班次、休班不误报超载，以及开放班次真实超载仍报警。批量和人员方案的原有检查也继续运行。

全量验证采用独立进程，按场景 JSON 构造模型，先执行 MRP（constraints=52、plantype=1）再运行 CP；没有执行 Django 中其他业务后处理，因此不能等同于已验证在线环境整条流程。
